# Техническое задание: редактор учебной игры «Лото»

Версия 1.0 • 16 сентября 2026 года

## 1. Назначение и результат разработки

Создать браузерный редактор, в котором учитель без программирования собирает учебную игру по мотивам русского лото. В клетках билетов находятся задания, на бочонках — ответы. Ученик выбирает количество билетов, решает задания и закрывает клетки бочонками. Ошибки уменьшают количество жизней.

Результат разработки: работающий редактор, автономный HTML-файл игры, переносимый файл проекта, экспорт кода для встраивания в Genially, исходный код и краткая инструкция для учителя. Данное ТЗ описывает будущий продукт; сам редактор в состав этого документа не входит.

Визуальный ориентир — приложенный скриншот: темный интерфейс, верхняя панель действий, настройки слева, крупный живой предпросмотр справа, округленные панели и цветовые акценты. Игровое оформление независимо от оформления редактора.

## 2. Принятые допущения

Следующие решения предложены для первой версии и могут быть изменены заказчиком:

- «Обратно» и «Вперед» означают отмену и повтор изменений редактора.
- «При нахождении героя» трактуется как наведение указателя на героя. На сенсорном экране аналогичное действие выполняется касанием. Поиск скрытого героя не входит в базовую механику.
- Это учебная адаптация лото: ученик выбирает клетку, после чего сверху появляются относящиеся к ней бочонки. Последовательное вытягивание единственного случайного бочонка ведущим не используется в первой версии.
- Один полностью решенный вопрос закрывает одну клетку и дает один собранный бочонок, в том числе для множественного выбора и порядка.
- Победа наступает при закрытии всех активных клеток всех выбранных билетов. Денежных ставок, выигрышей и многопользовательской игры нет.
- По умолчанию: русский язык, 3 жизни, выбор 1–3 билетов. Диапазон выбора задает учитель.

## 3. Интерфейс редактора

### 3.1. Верхняя панель

| Элемент | Поведение |
| --- | --- |
| «Обратно» | Отменяет последнее изменение текста, настройки, изображения или структуры проекта. |
| «Вперед» | Повторяет отмененное изменение. Новое действие после отмены очищает очередь повторов. |
| «Загрузить проект» | Открывает ранее сохраненный файл проекта с заданиями, оформлением и встроенными ресурсами. |
| «Сохранить проект» | Скачивает переносимый файл проекта для дальнейшего редактирования. |
| «Скачать HTML» | Скачивает готовую игру для запуска в браузере. |
| «Облегчить код» | Открывает настройки уменьшения размера экспорта и показывает результат оптимизации. |
| «Код для Genially» | Открывает окно подготовки и копирования кода встраивания опубликованной игры. |
| Статус сохранения | Различает «Есть изменения», «Черновик сохранен в браузере», «Проект выгружен в файл» и ошибку сохранения. |

История отмены — не менее 100 действий. Непрерывное перемещение ползунка и серия ввода в одном поле объединяются в логические действия. Поддержать Ctrl/Cmd+Z и повтор стандартным сочетанием; не нарушать обычное редактирование текста внутри полей. При недоступном действии кнопка неактивна.

### 3.2. Разделы настроек

«Дизайн», «Билеты», «Задания», «Бочонки», «Герой», «Правила», «Экраны». Панель настроек прокручивается независимо от предпросмотра.

### 3.3. Предпросмотр

Справа постоянно отображается игра с текущими настройками. Над ним: «Редактирование», «Тест», «Начать тест заново», переключение экранов «Старт», «Игра», «Задание», «Победа», «Поражение», выбор размера «Компьютер / Планшет / Телефон».

Режим редактирования позволяет выбирать объекты для настройки. Режим теста воспроизводит поведение ученика, включая жизни, проверку и завершение игры. Тестовые ответы не меняют содержание проекта. Переключение экранов предпросмотра не засчитывается как игровое действие.

## 4. Игровой сценарий

1. Ученик видит название, инструкцию и выбор количества билетов из разрешенного учителем диапазона.
2. После «Играть» получает выбранное количество разных билетов из подготовленного набора.
3. Вверху игрового поля расположена зона бочонков; ниже — билеты. Постоянно видны жизни и счет «Собрано: X из Y».
4. Ученик выбирает незакрытую клетку. Она подсвечивается, полный текст задания открывается в окне задания, сверху появляются варианты-бочонки либо элементы ответа для выбранного типа задания.
5. Ученик составляет ответ и нажимает «Проверить».
6. При правильном ответе бочонок плавно перемещается на выбранную клетку. Клетка закрывается, счет увеличивается на 1. Для сложных типов используется итоговый бочонок с заданной учителем короткой подписью.
7. При неверном ответе снимается ровно одна жизнь за одну проверку. Клетка остается открытой, ученик получает сообщение и может попробовать снова.
8. Когда закрыты все активные клетки, показывается победа. Когда жизни достигли нуля — поражение; дальнейшие ответы блокируются.

Пустой ответ не считается ошибкой: кнопка проверки неактивна, показана понятная подсказка. Выбор вариантов и смена клетки сами по себе не снимают жизни. При возвращении в открытую клетку сохраняется незавершенный ответ текущего сеанса. После ошибочной проверки повторная проверка того же неизмененного ответа заблокирована до его изменения.

Закрытая клетка не принимает новые ответы и не увеличивает счет повторно. На время обработки проверки и анимации повторные нажатия блокируются. «Играть снова» сбрасывает жизни, счет и ответы. Перезапуск или уход из незавершенной игры требует подтверждения.

## 5. Билеты

Учитель создает, копирует, переименовывает и удаляет билеты; редактирует сетку и назначает задания отдельным клеткам. Активная клетка содержит ровно одно задание. Пустая декоративная клетка не участвует в проверке и подсчете результата.

Предусмотреть два шаблона:

- «Классический»: 3 строки × 9 столбцов, 15 активных клеток, по 5 в каждой строке, остальные пустые.
- «Учебный»: прямоугольная сетка от 2 × 2 до 5 × 9, активность каждой клетки настраивается.

Длинные задания отображаются в клетке сокращенно, полностью — в окне задания. Учитель задает краткую подпись клетки отдельно. При смене размера сетки задания не удаляются незаметно: вытесненные задания остаются в банке, редактор сообщает об изменении.

Выбор ученика — от 1 до 6 билетов, но не более количества валидных билетов в проекте. Учитель ограничивает диапазон. Для первой версии билеты выбираются случайно без повторений; одинаковый билет дважды за сеанс не выдается. На узком экране билеты располагаются вертикально либо переключаются вкладками с видимым общим прогрессом.

Повторное использование задания в разных клетках разрешено: прогресс учитывается для каждой конкретной клетки. Максимальное число собираемых бочонков равно сумме активных клеток выданных билетов.

## 6. Редактор заданий и ответов

Для каждого задания: идентификатор, тип, полный текст, короткая подпись клетки, варианты/эталоны ответа, пояснение после проверки, подпись итогового бочонка. Поддержать добавление, копирование, удаление, поиск и назначение из банка заданий в клетки билетов.

| Тип | Что вводит учитель | Действие ученика | Условие правильности |
| --- | --- | --- | --- |
| Один ответ | 2–8 вариантов, ровно один правильный | Выбирает один бочонок и нажимает «Проверить» | Выбран правильный вариант |
| Множественный выбор | 2–8 вариантов, один или несколько правильных | Отмечает несколько бочонков и нажимает «Проверить» | Набор выбранных идентификаторов точно совпадает с эталоном |
| Ввод ответа | Один или несколько допустимых текстовых ответов | Вводит ответ в поле и нажимает «Проверить» | Ввод совпал с одним из эталонов после заданной нормализации |
| Расстановка по порядку | 2–8 элементов в правильной последовательности | Расставляет бочонки и нажимает «Проверить» | Последовательность идентификаторов совпадает с эталоном |

Для ввода ответа по умолчанию удаляются пробелы по краям и игнорируется регистр. Отдельные настройки: учитывать регистр, считать «е» и «ё» равными, сворачивать повторные пробелы. Произвольные математические выражения не вычисляются: для допустимых форм записи учитель задает альтернативные ответы.

Для ввода ответа правильный ответ не показывается на бочонке до проверки: сверху отображается нейтральный бочонок с символом «?», после успеха он получает заданную итоговую подпись и закрывает клетку.

Для множественного выбора и порядка один итоговый бочонок закрывает клетку после полного правильного решения. Частичные ответы не закрывают клетку и не начисляют дробные очки. Одна неверная проверка снимает одну жизнь независимо от числа ошибок внутри ответа.

Варианты перемешиваются при первом открытии клетки и сохраняют порядок при повторной попытке. Для порядка начальная последовательность должна отличаться от правильной. Перетаскивание дополняется кнопками перемещения и клавиатурным управлением.

Совпадающий текст не является идентификатором ответа: связи хранятся по устойчивым ID. Редактор предупреждает об одинаковых видимых вариантах внутри одного задания.

## 7. Внешний вид и ресурсы

### 7.1. Фон

Загрузка PNG, JPEG или WebP; удаление и замена; однотонный цвет; режимы «Заполнить», «Вписать», «Повторять»; позиция, затемнение и прозрачность наложения. Пропорции изображения сохраняются. До готовности нового изображения старое остается видимым, после декодирования выполняется замена без пустого кадра.

### 7.2. Герой

Загрузка PNG/WebP с прозрачностью или JPEG. Настройки: показать/скрыть, положение, размер, зеркальное отражение, прозрачность. Перемещение мышью и точные координаты в процентах игрового поля. Герой не перекрывает интерактивные элементы по умолчанию.

Эффекты героя: мигание, цветное тонирование силуэта, свечение. Учитель задает цвет, интенсивность, длительность и событие: наведение/касание, правильный ответ, ошибка, победа. Эти события переключаются независимо. Для картинки с прозрачностью окрашивается силуэт; для JPEG — прямоугольное изображение с предупреждением в настройках.

Мигание — плавное изменение прозрачности до 2 циклов в секунду, без резких вспышек. Режим уменьшенной анимации заменяет мигание статичной подсветкой.

### 7.3. Настраиваемые элементы

Для билета, клетки, бочонка, окна задания и кнопки «Проверить»: цвет фона и текста, рамка, скругление, размер шрифта. Для выбранного, правильного и ошибочного состояния — отдельные цвета, подсветка и толщина рамки. Для окна задания — также прозрачность и тень. Для кнопок — надпись и состояния «обычное», «наведение», «нажато», «неактивно».

### 7.4. Шрифты и языки

Список шрифтов первой версии: Arial, Verdana, Georgia, Trebuchet MS, Nunito, Roboto, Open Sans. Системные шрифты используют резервный стек; выбранные несистемные шрифты с разрешающей встраивание лицензией включаются в экспорт, включая кириллицу. Шрифт, размер и насыщенность настраиваются глобально и при необходимости для отдельных элементов.

Языки интерфейса редактора и интерфейса игры задаются отдельно. Первая версия: русский, английский, украинский, казахский. Переводятся системные кнопки, сообщения и инструкции. Учительский текст заданий автоматически не переводится. Предусмотреть редактирование видимых системных надписей и расширяемые словари локализации.

## 8. Жизни, счет и финальные экраны

Количество жизней: 1–10, по умолчанию 3. Список значков: ❤️ 💛 💚 💙 💜 ⭐ 🌟 🍀 🔥 🐾; отдельное поле для собственного эмодзи. Форматы: повторяющиеся значки или «эмодзи × число». Потерянные жизни скрываются либо становятся полупрозрачными — по настройке.

Счет отражает число закрытых клеток, а не число выбранных вариантов. Формат «Собрано бочонков: 7 / 15» редактируется и переводится. Дополнительный индикатор показывает прогресс каждого билета.

Учитель редактирует стартовый экран, победу и поражение: заголовок, текст, цвета, изображение, подписи кнопок. На финальном экране показываются собранные бочонки и число ошибок. Предусмотреть «Играть снова» и «На главный экран».

## 9. Живой предпросмотр и производительность

Все изменения применяются автоматически. Отдельная кнопка «Применить» не требуется. Нельзя полностью перезагружать страницу, пересоздавать iframe или заменять всю игровую сцену при изменении одного поля.

Использовать единое состояние проекта, точечное обновление элементов, устойчивые идентификаторы и переиспользование загруженных ресурсов. Движок игры должен быть общим для предпросмотра и HTML-экспорта.

Изменения цветов, текста, положения и размеров сохраняют фокус ввода, положение прокрутки и текущий тестовый прогресс. Изменение правил, набора билетов или правильных ответов в режиме теста явно сбрасывает тестовую сессию, показывает уведомление и сразу отображает актуальные данные. Скрытый сброс при изменении оформления недопустим.

Измеримые требования на согласованном контрольном ноутбуке: 4 ядра, 8 ГБ ОЗУ, актуальный стабильный Chrome, проект до 6 билетов по 15 заданий и 20 МБ ресурсов:

- Для 95% обычных изменений отклик предпросмотра — не более 100 мс после события ввода.
- Перетаскивание и ползунки — не менее 30 кадров/с, целевой показатель 60 кадров/с.
- Нет белых/пустых кадров, скачка прокрутки и потери фокуса при серии из 100 изменений.
- Сохранение и оптимизация не блокируют взаимодействие длительными синхронными операциями; тяжелая обработка выполняется порциями или в Worker.
- Для операций дольше 500 мс показываются статус и, где применимо, возможность отмены.

Декодирование крупных файлов измеряется отдельно от обычного редактирования. При превышении рекомендуемых размеров редактор предлагает сжатие. Точные условия замеров фиксируются в отчете приемки.

## 10. Проект, автосохранение и проверка данных

Формат проекта — один файл `.loto.json`: версия схемы, метаданные, настройки игры, оформление, словари, банк заданий, билеты, связи клеток и ресурсы со встроенными данными. Проект полностью переносится на другой компьютер без ссылок на локальные пути.

Состояние тестового прохождения хранится отдельно и не включается в авторский проект. Черновик автоматически сохраняется в браузере после изменений с небольшой задержкой. При открытии редактора предлагается восстановить черновик. Ошибка или недоступность браузерного хранилища отображается явно; ручная выгрузка файла остается доступной.

При загрузке проверяются формат, версия, идентификаторы, связи, типы и размеры ресурсов. Ошибка импорта не уничтожает открытый проект. Замена проекта при несохраненных изменениях требует подтверждения. Более новая неподдерживаемая версия открывается с понятным отказом, а не частичной потерей данных.

Перед экспортом проверять: наличие активных заданий, заполненность ответов, корректность сеток, доступное число билетов, отсутствие потерянных ресурсов и ссылок. Ошибки показываются списком с переходом к проблемному полю. Нельзя экспортировать игру, которую невозможно завершить из-за некорректной конфигурации.

## 11. HTML-экспорт и «Облегчить код»

«Скачать HTML» создает один файл `.html` с игровым движком, стилями, данными, изображениями и необходимыми шрифтами. Игра запускается открытием файла в настольном браузере без сервера и доступа к интернету. В экспорт не включаются панель редактора и история отмен. Игра также должна работать при размещении этого файла на статическом HTTPS-хостинге.

Кнопка «Облегчить код» предлагает:

- убрать неиспользуемые ресурсы из экспортной копии;
- уменьшить разрешение и качество изображений с сохранением прозрачности;
- исключить неиспользуемые начертания шрифтов;
- минимизировать HTML, CSS, JavaScript и данные без изменения игровой логики.

Показывать размер до и после и разницу в процентах. Оптимизация создает отдельный вариант экспорта; исходный проект и оригиналы изображений сохраняются. Для сжатия изображений доступно сравнение качества. Нельзя обещать фиксированное сокращение размера: при отсутствии выигрыша показать это явно.

## 12. «Код для Genially»

Предусмотреть интеграцию через iframe с HTTPS-адресом опубликованной игры. Диалог содержит адрес игры, размеры, адаптивный режим, код и кнопку «Копировать». Локальный путь к скачанному HTML не принимается как адрес публикации.

Эта кнопка не должна обещать, что произвольный HTML/JavaScript можно непосредственно вставить и выполнить в Genially. Если игра еще не размещена, показать инструкцию: скачать HTML → разместить на подходящем HTTPS-хостинге → указать адрес → скопировать код. Автоматическая публикация и оплата хостинга в первую версию не входят.

Хостинг должен разрешать встраивание; код не должен использовать временные `blob:`-адреса. Совместимость проверяется на опубликованном материале Genially в целевом аккаунте, включая касания, ввод текста, прокрутку и изменение размеров. Доступность встраивания в целевом аккаунте — внешняя зависимость, которую исполнитель проверяет в начале разработки.

Основание для отдельной проверки: официальный справочный центр Genially описывает возможные проблемы отображения встроенных внешних страниц: [Genially Help Center](https://help.genially.com/). Данный документ задает предполагаемый путь интеграции, а не гарантирует ограничения конкретного тарифа или поддержку прямой вставки скриптов.

## 13. Совместимость и обработка ошибок

Проверить последние две стабильные основные версии Chrome, Edge, Firefox и Safari на момент сдачи. Редактор рассчитан на компьютер и планшет; игра — также на телефон от 360 px шириной и на iframe. На телефоне не должно быть горизонтальной прокрутки всей страницы; масштаб, переносы или вкладки должны сохранять читаемость заданий.

Управление мышью, касанием и клавиатурой. Видимый фокус, текстовое сообщение дополнительно к цвету, режим уменьшенной анимации. Системные ошибки сообщаются понятным текстом без потери проекта.

Текст заданий и загруженные данные не выполняются как код. Ресурсы проверяются по реальному типу и лимитам. Не использовать eval для ответов или проекта. Размер одного изображения ограничить 10 МБ, рекомендуемый общий объем ресурсов — 20 МБ; при превышении предложить уменьшение, при невозможности загрузки показать причину.

## 14. Критерии приемки

| Проверка | Ожидаемый результат |
| --- | --- |
| Загрузка фона и героя | Изображения сразу видны, настройки позиции и масштаба работают, пустой кадр отсутствует. |
| Серия изменений оформления | Текст, цвета, шрифт, подсветка и кнопки обновляются без перезагрузки, потери фокуса и сброса игры. |
| Отмена и повтор | Возвращаются предыдущие значения, удаленные объекты и назначенные изображения. |
| Сохранение и загрузка | На другом компьютере восстанавливаются задания, билеты, оформление и все ресурсы. |
| Поврежденный проект | Выдается ошибка; текущий проект сохраняется. |
| Выбор числа билетов | Выдаются разные билеты в указанном количестве, сверх доступного выбрать нельзя. |
| Один правильный ответ | Бочонок закрывает выбранную клетку, счет увеличивается ровно на 1. |
| Неправильный ответ | Снимается одна жизнь, клетка остается открытой. Двойной клик не снимает две жизни. |
| Множественный выбор | Правильным считается только полный эталонный набор. |
| Ввод ответа | Альтернативные ответы и настройки нормализации работают; ответ заранее не раскрывается. |
| Порядок | Проверяется вся последовательность, доступны перетаскивание и кнопки. |
| Повторный ответ в закрытой клетке | Жизни и счет не меняются. |
| Одинаковые ответы в разных заданиях | Проверка идет по текущей клетке и ID, чужая клетка не закрывается. |
| Жизни закончились / все клетки закрыты | Показывается соответствующий финальный экран, дальнейшая проверка блокируется. |
| Эффект героя | Выбранное событие включает заданное мигание/цвет; на телефоне работает касание. |
| Автономный HTML | Все четыре типа заданий работают без сети; фон, герой и выбранный встроенный шрифт доступны. |
| Оптимизированный HTML | Правила, ответы, жизни и счет совпадают с обычным экспортом; исходный проект сохранен. |
| Genially | Опубликованная игра встраивается и проходит полный тестовый сеанс в целевом аккаунте. |
| Производительность | Выполнены показатели раздела 9; замеры и конфигурация приложены к сдаче. |

## 15. Комплект сдачи

Исполнитель передает редактор, исходный код с инструкцией сборки и запуска, описание формата проекта, демонстрационный проект с четырьмя типами заданий, обычный и оптимизированный HTML-экспорт, пример iframe-кода, инструкцию для учителя и отчет по критериям приемки.

В демонстрационном проекте должно быть не менее трех билетов; предусмотрены задания для проверки правильного и неправильного ответа, победы, поражения, совпадающих текстов ответов и длинных формулировок. Основной приоритет: корректная учебная механика, сохранность проекта и плавный предпросмотр.
